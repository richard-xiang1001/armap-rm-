## Expected Validation Pattern

- `pair_accuracy` should not regress materially versus v0.3.0 baseline.
- `gap_p50` stability and truncation robustness (`max_len 512 -> 384`) should be evaluated via ablations.

## Reference Ablation Evidence (4090, precheck)

Dataset/split:
- train: `data/real_v030_precheck/train.jsonl` (5,000)
- valid: `data/real_v030_precheck/valid.jsonl` (500)

Single-variable ablations (`seed=42`, `epochs=3`, `max_steps=4000`, `batch_size=256`, `bf16`, `cuda`):

- `flat + mean` (`results/v031_flat_mean_512`)
  - best valid `pair_accuracy = 0.582`
- `stepwise + mean` (`results/v031_stepwise_mean_512`)
  - best valid `pair_accuracy = 0.582`
- `stepwise + last_k_step(k=3)` (`results/v031_stepwise_lastk_512`)
  - best valid `pair_accuracy = 0.586` (best among 512-length runs)

Truncation sensitivity check (`stepwise + last_k_step`):
- `max_len=512` eval:
  - `pair_accuracy = 0.586`
  - `gap_p50 = 0.006407078355550766`
- `max_len=384` eval (`results/v031_stepwise_lastk_384`):
  - `pair_accuracy = 0.588`
  - `gap_p50 = 0.005827473476529121`

Interpretation:
- Step-structured input does not regress against flat baseline.
- `last_k_step` pooling provides a small but consistent gain on this setup.
- Reducing max_len from `512 -> 384` does not degrade pair ranking quality in this run.

Note:
- This is a precheck record on generated data lineage (`example_episodes_v030` -> `real_v030_precheck`).
